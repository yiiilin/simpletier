# 多协议虚拟组网设计方案

**最小配置 · 三平台虚拟网卡 · SOCKS5 / HTTP Proxy · 动态路由**

版本：v0.2（设计草案） ｜ 日期：2026-09-21  
基于 v0.1 重构：节点间仍可仅使用 TCP；节点内新增完整 IP 分组接入。

## 01 设计结论与能力范围

采用“一套控制平面、两类数据平面、独立系统后端”。L3 Packet 平面透传完整 IP 包；L4 Flow 平面分别提供 TCP 字节流与 UDP 数据报。节点身份、地址分配、拓扑同步、选路和认证由两者共用。

**本版替换 v0.1 的关键假设：TUN 不再默认拆解、终止所有 TCP 连接，而是转发原始 IP 包。** 三种系统网卡都归一化为 PacketDevice，由两端操作系统处理 TCP、UDP 和 ICMP；只有代理接入或特殊转换才需要 SocketEndpoint / 用户态网络栈。[1][2][3][4]

| 接入方式 | TCP | UDP | ICMP | 定位与边界 |
| --- | --- | --- | --- | --- |
| Linux TUN | 支持 | 支持 | 支持 | 三层 IP 分组读写，非 TAP / 以太网桥接。 |
| Windows Wintun | 支持 | 支持 | 支持 | 三层 IPv4 / IPv6 包；需驱动及系统配置。 |
| macOS utun | 支持 | 支持 | 支持 | 平台包装头在后端剥离，核心只接触 IP 包。 |
| SOCKS5 | CONNECT | UDP ASSOCIATE | 不支持 | 不把 SOCKS5 宣称为 ICMP 网关。[5] |
| HTTP 正向代理 | HTTP、CONNECT | 普通代理不支持 | 普通代理不支持 | UDP / IP 需要另行实现扩展。[6][7][8] |

表中是目标交付范围，不表示已有实现。默认虚拟地址族为 IPv4；启用选填 IPv6 前缀时，IPv6 转发及必要 ICMPv6 行为也必须通过验收，不能只开放 TCP6。[13][15]

### 两个不能混淆的“TCP”

内层是用户业务：TCP、UDP、ICMP。外层是节点间载体：TCP、WS/WSS、HTTP 隧道或私有协议。**外层只允许 TCP，仍然能封装内层 UDP / ICMP，但不能消除 TCP 的可靠有序传输和队头阻塞带来的代价。**[9][10]

### 非目标与交付边界

默认不提供二层广播、ARP 桥接、全网组播、自动公网出口或任意 NAT 穿透。覆盖网络内互访不要求每个中继创建 TUN，也不要求中继启用操作系统 IP forwarding。互联网出口、局域网网关及完整流恢复均为独立可选能力。

文档中的结构、接口、帧名、端口和时间阈值是设计建议；尚未形成可互操作的线协议，也未完成实现验证、压测或安全审查。

## 02 最小配置与接入开关

保留五类基础信息：本地监听、零到多个上游、网络名称、虚拟网段、认证 Token。

```yaml
listen:
  - "tcp://0.0.0.0:7000"
upstreams:
  - "tcp://relay-a.example.com:7000"
  - "ws://relay-b.example.com:7001"
network:
  name: "my-network"
  cidr: "10.77.0.0/24"
  token: "${MESH_TOKEN}"
```

上游必须包含主机或域名，只有协议和端口不能定位远端。cidr 是整个网络的地址池，不是本节点地址。upstreams 省略等于空列表；同网节点的名称、规范化前缀和有效入网凭据必须匹配。环境变量缺失或解析为空时拒绝启动。

### 同时启用三层网卡与两个本地代理

只追加以下选填块；不要求用户指定 TUN、Wintun 或 utun，Agent 根据系统选择后端。

```yaml
inbounds:
  tun: true
  socks5: "127.0.0.1:1080"
  http_proxy: "127.0.0.1:8080"
```

| 配置 / 运行形态 | 默认行为 |
| --- | --- |
| Agent 的 tun | 默认开启；权限或驱动不足明确失败，不静默降级。 |
| SOCKS5 / HTTP 入口 | 默认关闭；填写地址后开启，避免无意启动代理端口。 |
| 纯中继节点 | 选填 inbounds.tun: false；仍可转发 Packet / Flow。 |
| 嵌入式 Go 库 | 默认不创建系统网卡、不改路由；由宿主显式挂载接入。 |
| 代理访问范围 | 默认仅本虚拟网络；外部地址必须有显式允许的出口。 |
| 代理公网监听 | 默认拒绝无认证的非回环监听；需选填认证与 ACL。 |

TCP、WS 等 listen / upstreams 是“组网连接”；inbounds 是“业务入口”，二者不能共用含糊的协议注册语义。SOCKS5 的 UDP 关联还会使用本地 UDP 监听，默认自动分配并在协议响应中返回；组网链路仍然可以全部使用 TCP。[5]

其他选填项包括固定 IP、state_dir、MTU、relay、访问策略、路由档位、代理认证、DNS、出口和 IPv6 前缀。未启用功能不要求用户填写对应参数。

## 03 模块分层与核心对象

```text
系统应用 -> TUN / Wintun / utun -> PacketRouter -> IP_PACKET
本地应用 -> SOCKS5 / HTTP       -> FlowRouter   -> STREAM / UDP_DATAGRAM
                                      |
                共同使用 Identity / Address / Topology / Policy
                                      |
                RoutePlanner -> Path / Circuit -> SecureLink
                                      |
                         TCP / WS / HTTP / Private Carrier
```

| 模块 | 职责 |
| --- | --- |
| PacketDevice | 归一化系统 IP 包读写、批处理、MTU 和设备事件。 |
| SystemNetwork | 配置地址、路由与可选 DNS；记录所有权并回滚。 |
| Proxy Adapter | SOCKS5、HTTP、私有业务入口；负责协议语义。 |
| PacketRouter | 以目的 IP 解析 NodeID，转发完整 IP 包。 |
| FlowRouter / Endpoint | 以目的 IP＋端口解析目标，打开 TCP / UDP 出口。 |
| RoutePlanner / Health | 路径约束、稳定性评分、主备选择、迟滞切换。 |
| Path / Circuit | Path 承载可独立交付消息；Circuit 承载有状态字节流。 |
| SecureLink / Carrier | 已认证邻接、多路复用、载体接入和物理连接管理。 |

### 对象必须分离

NodeID 是稳定身份；VirtualIP 是可变地址；LinkID 区分同邻居的并行连接；PathID / Generation 标识一条已安装转发路径；CircuitID 是一次字节流线路；AssociationID 标识一个 UDP 代理关联；SessionID 标识独立于路径的端到端状态。

**UDP_DATAGRAM 不是 IP_PACKET。** 前者包含逻辑目的地址和 UDP 载荷，由出口创建 UDP socket；后者包含完整 IP 头和运输层内容，直接注入目标网卡。两者共享路径与消息调度，但不能混用解析器、校验规则或地址语义。

### 路由不依赖接入协议

中继不必理解 HTTP 方法、WebSocket 消息或目标系统网卡类型。Carrier 注册在组网层，Adapter 注册在业务层，PacketDevice 注册在平台层。不能把所有东西强制包装为 net.Conn；消息边界和 IP 元数据必须有自己的接口。

## 04 三层转发与代理互通路径

### TUN 到 TUN：由端点内核保持传输层状态

```text
A 应用 / 内核：10.77.0.10 -> 10.77.0.20
   -> A 虚拟网卡 ReadPacket
   -> 按目的 IP 找到 B 的 NodeID
   -> 加密 IP_PACKET -> R1 / R2 中继
   -> B 解密、校验源地址与策略
   -> B 虚拟网卡 WritePacket
   -> B 内核 / 应用
```

回包走相反的逻辑处理，路由可独立选择。网卡读出方向是“宿主待发送”；写入方向是“从网络接收并注入宿主”。源、目的虚拟 IP 和端口不做默认 NAT；宿主内核处理 TCP 重传、UDP 投递以及 ICMP 响应。[1][3][9][14]

因此，原始 IP 透传不需要为每个 TCP 连接建立一个代理出口，也不需要先实现用户态 TCP 栈。目标服务必须监听虚拟地址或通配地址，且宿主防火墙允许访问。仅监听 127.0.0.1 的服务不会自动暴露。

### SOCKS5 / HTTP 到远端系统服务

默认走 L4 Flow：入口把目标虚拟 IP 解析成目标 NodeID，创建 Stream 或 UDP Association；目标节点通过 SocketEndpoint 连接它自己持有的虚拟 IP＋端口。没有系统网卡的目标，可投递到 SDK 注册的虚拟端口；都不存在则明确拒绝。

这种代理转发通常不保留客户端原始源 IP。覆盖网络 ACL 使用经过认证的来源 NodeID 与入口身份；不能依赖目标应用看到的 socket 对端地址代替授权。需要保留入口节点虚拟源 IP 时，可选用户态网络栈把代理 Flow 转成 IP 包，再进入 Packet 平面。[21]

### 不创建隐式环路与出口

SocketEndpoint 只接受“本节点拥有的虚拟地址”或明确注册的服务映射，不把失败的本地访问再次送回覆盖路由。访问其他物理地址、LAN 或公网必须选中声明了相应能力的 Gateway，并同时通过来源与目标策略校验。

**纯中继只转发加密的覆盖消息，不把过境包注入自己的 TUN。** 这样中继不需要 TCP / UDP / ICMP 的本地终止逻辑，平台差异只留在业务端点。

## 05 Linux TUN 与 Windows Wintun 后端

### Linux：标准化为无附加头的 IP 包

后端打开 /dev/net/tun，通过 TUNSETIFF 创建 IFF_TUN | IFF_NO_PI 设备。不开 IFF_TAP；第一版不启用需要额外处理的 VNET_HDR / GSO 元数据。Linux 文档明确区分 TUN 的 IP 包和 TAP 的以太帧；创建设备通常需要 CAP_NET_ADMIN 或相应预创建授权。[1]

建议以 rtnetlink 配置地址、接口状态、MTU 和路由，避免在库内部拼接 shell 命令。初版单读单写、单队列；后续再启用 multiqueue 与批量收发，并验证所有 offload 路径输出的是可发送的完整 IP 包。

权限处理由 Agent 或小型特权 helper 完成；核心路由库不要求长期以 root 身份运行。容器部署须显式提供 TUN 设备及所需权限，不能只因二进制启动成功就报告虚拟网卡已就绪。

### Windows：驱动、包环与系统配置拆开

Wintun 提供三层包读写，接收得到 IPv4 / IPv6 包指针；使用结束必须释放。发送先分配发送包内存，再提交。无可读数据时等待事件，不忙轮询；环满时采用有界丢弃和统计，不无限复制到 Go 堆。[2][3]

```text
创建 / 打开 Adapter -> 获取 LUID -> 启动 Session
ReceivePacket -> 复制到自有缓冲 -> ReleaseReceivePacket
AllocateSendPacket -> 填充 IP 包 -> SendPacket
停止读写 -> EndSession -> CloseAdapter
```

**不能在 ReleaseReceivePacket 后继续让 goroutine 引用同一内存。** 第一版优先明确复制和所有权，再评估零拷贝优化。

地址与路由单独通过 IP Helper / NetIO API 配置，例如 CreateUnicastIpAddressEntry、CreateIpForwardEntry2；这些操作有管理员权限要求，Wintun 收发接口本身不能替代路由配置。[11][12]

使用固定的应用状态生成适配器标识，记录实际 LUID；不要每次启动无条件创建新适配器。随安装包分发官方签名、匹配架构的 DLL，并在发布前审核对应分发许可与签名完整性。[2][3]

### 两平台共同验收

网卡可读写、虚拟地址存在、网段路由命中、回包路径正确、宿主防火墙可诊断、重复启动不产生冲突对象、退出仅清理本实例资源。进程崩溃后重启应能识别并修复自有残留状态。

## 06 macOS utun 与系统网络生命周期

### macOS 两种部署形态，共享核心

命令行 / 守护进程后端可参考 wireguard-go 的 utun 实现：使用系统控制接口连接 com.apple.net.utun_control，读取真实 utunN 名称。直接 utun I/O 带有 4 字节地址族前缀；读取时剥离，写入时按 IPv4 / IPv6 添加，不能发给另一系统的 TUN。[4]

面向桌面应用，建议单独提供 Network Extension 适配层，通过 NEPacketTunnelProvider 对接系统网络生命周期；现有 WireGuard Apple 代码可作为这种集成形态的参考。[22] 设计上由 Swift / Objective-C 边界把系统 packet flow 转成同一 PacketDevice 契约，不从私有字段猜测文件描述符。

桌面分发须单独验证目标 macOS 版本、签名、entitlement、扩展安装和用户授权条件。它们属于发布与安装要求，不应塞进五类组网配置。原生 utun 和 Network Extension 两条路径均需真机集成测试；不能把命令行原型等同于可直接上架的桌面产品。

### SystemNetwork 是可回滚事务

```text
校验配置 / 权限 / 网段冲突
 -> 保存本实例状态与变更计划
 -> 创建虚拟设备并分配节点地址
 -> 设置 MTU、虚拟网段路由
 -> 启动数据处理并宣布能力就绪
 -> 持续处理网络切换、地址变化和设备事件
 -> 停止接入、撤销声明、逆序清理自有资源
```

默认只安装虚拟网段路由，不修改默认路由，不接管全系统 DNS，不关闭防火墙。不覆盖其他 VPN、物理网卡、Docker / 虚拟机的冲突路由。基础策略遇到冲突时明确失败，允许用户选填改网段或更精细策略。

### 防止组网连接被自己捕获

Carrier 拨号必须经过 UnderlayDialer，确保目标上游仍走物理网络。默认分流降低风险，但不能代替校验：域名解析后可能落入虚拟网段；启用全隧道或出口时必须配置上游绕行，跟踪物理默认路由和地址变化，避免隧道递归。

所有地址、路由、DNS 和防火墙变更都记录所有权。退出不“恢复整个系统快照”，只删除或回滚本实例确实创建且未被外部修改的对象；避免覆盖其他软件在运行期间作出的合法变更。

## 07 SOCKS5：TCP 与 UDP 分开实现

### TCP CONNECT

完成方法协商与可选客户端认证，解析 IPv4、IPv6 或域名目标；经策略与解析器确定实际目的地，再通过 FlowRouter 打开远端流。目标就绪后返回成功响应，然后双向拷贝，支持半关闭与取消。[5]

BIND 可暂不实现，但必须返回明确的“命令不支持”。第一版支持 NO AUTH 的本机回环入口与选填用户名 / 密码；这是声明过的兼容子集，不宣称完整实现 RFC 1928 所有认证要求。

### UDP ASSOCIATE 是关联，不是一条可靠字节流

```text
客户端 --TCP 控制连接--> SOCKS5 入口
客户端 --UDP 数据报----> 本地 UDP relay
                    -> UDP_DATAGRAM -> 多跳路径
                    -> 目标节点的 UDP socket
回包按 AssociationID 和实际源地址返回
```

关联由 TCP 控制连接持有；控制连接结束就释放关联。本地 UDP 接口返回客户端可达的 BND.ADDR / BND.PORT，并验证 UDP 来源与该关联匹配。SOCKS5 UDP 报文有地址和 FRAG 字段；不实现 SOCKS 分片重组时，只接受 FRAG=0，按规范丢弃其他分片。[5]

### 内部状态与投递规则

每个关联记录认证入口、客户端地址、目的映射、选定出口、空闲时间、配额与 AssociationID。一个关联可以面向多个目的地；为每个“关联＋已授权目的”建立受限 UDP flow，不能把整个关联误当成单一目标。

源节点封装目的地址与 UDP 载荷；出口创建 UDP socket 并记录回包源。帧长度保留数据报边界，允许合法零长度 UDP 载荷。可设置默认 120 秒空闲回收及每关联目标数上限，但这些是可覆盖的初值，不是所有 UDP 应用通用超时。

换中继路径时仍使用原 AssociationID 与原出口 socket，避免无意改变出口源端口；如果出口节点或 socket 状态丢失，明确报告关联丢失，不把“重建新端口”冒充原关联恢复。

**默认不做业务级 UDP ACK、重放或去重。** 仅对同一个覆盖消息序号做防重放；两次内容相同的 UDP 消息仍可能都是合法业务。UDP 不承诺可靠交付，拥塞治理及消息过期必须独立设计。[16]

## 08 HTTP Proxy 与载体扩展

### HTTP 正向代理的交付范围

支持普通 HTTP 请求转发、HTTPS 的 CONNECT 隧道、流式上传、流式响应、长轮询，以及经过 CONNECT 的 WebSocket。HTTP/1.1 明文 WebSocket Upgrade 另行正确处理 101 后的双向转发；不默认执行 HTTPS 中间人解密。[6]

请求头、代理凭据、逐跳字段、Body、Trailer、取消、连接池和超时均由 HTTP Adapter 负责。普通请求可经远端 Flow Dialer 连接目标虚拟端口；CONNECT 在目标流建立后返回成功，再转发字节，不把隧道内容解析成 HTTP。[6]

请求 / 响应都应增量处理，不能为了“非流式接口”把整个 Body 读入内存。Go HTTP/1 按需要启用全双工并及时 Flush；HTTP/2 处理方式不同，要测试代理链中的缓冲、流控与超时。HTTP Transport 的连接复用意味着路由变化未必立即影响已复用连接。[17]

### 不把请求失败当作安全重试许可

在没有业务幂等证据时，不能因线路断开重放非幂等请求。路由层只返回路径 / 连接错误；请求级重试由 Adapter 在剩余预算内判断，结果未知时明确上报。[6]

### HTTP Proxy 与 HTTP Carrier 不是同一配置项

```text
inbounds.http_proxy -> 接受业务客户端的正向代理请求
upstreams 的 HTTP   -> 节点之间承载组网帧的隧道
```

TCP、WS/WSS、HTTP CONNECT 隧道可统一提供可靠双向 Carrier；现有 Yamux 等复用库可用作候选，但不提供你的路由和恢复语义。[23] 仅允许短请求的 HTTP 环境须用独立 httppoll 适配器实现上下行、序号、去重、有限邮箱与反压。

### UDP / ICMP 的 HTTP 扩展边界

普通 CONNECT 提供 TCP 隧道。需要标准化 HTTP UDP 代理时，另实现 RFC 9298 的 CONNECT-UDP；需要 IP 隧道时，另实现 RFC 9484 的 CONNECT-IP，不应把它们默认算进普通 HTTP Proxy 的兼容能力。[6][7][8]

CONNECT-UDP 并非只能运行在 QUIC：HTTP Datagrams 的 Capsule 机制也能通过可靠流承载；但这仍具有可靠流的阻塞特征。客户端与服务器都必须实现并协商相关扩展。[7][18]

## 09 消息封装与端到端安全

### 区分三个业务载荷

| 消息类型 | 载荷与交付目标 |
| --- | --- |
| IP_PACKET | 完整 IPv4 / IPv6 分组；最终交给 PacketDevice。 |
| UDP_DATAGRAM | AssociationID、目的 / 来源地址、UDP 载荷；最终交给 UDP Endpoint。 |
| STREAM_DATA | 某 Circuit 的连续字节；遵守 FIN / RESET 与流量窗口。 |

控制面另定义 HELLO、ADVERTISEMENT、PATH_OPEN / READY / ERROR、PROBE 等消息。HTTP、WS 和 TCP 的读取边界不等于覆盖帧边界：必须有长度定界、类型与版本，先检查尺寸再分配内存。

```text
可见路由信封：Version, Kind, NetworkID, SrcNodeID, DstNodeID,
              PathID, PathGeneration, OverlayHopLimit, Length
端到端消息头：SessionID, KeyEpoch, MessageNumber, PayloadType
受认证载荷：  IP_PACKET / UDP_DATAGRAM / STREAM 数据
```

字段列表为逻辑模型，不是已经冻结的二进制布局。控制消息与业务消息有不同上限；初值可设单个完整帧不超过 64 KiB，超长消息须显式分块，禁止无界长度或隐式拼接。

### 加密状态不绑定单条中继路径

节点间连接先完成身份与入网认证。数据还应在源 / 目的节点建立端到端安全上下文，绑定 NetworkID、双方 NodeID、不可变消息头和载荷。这样中继能转发，但不能伪造其他节点的业务来源。

KeyEpoch / MessageNumber 与路径代际分离，换路不复用 AEAD nonce。相同密文帧的重放按安全窗口丢弃；合法 IP / TCP 重传在重新进入封装时分配新的消息编号，不能用“内层包内容相同”判为攻击。

可修改的跳数 / 局部路径标签不能直接纳入不可变端到端认证字段；由逐跳安全链路保护，并在协议中明确哪些字段可由中继修改。来源、最终目的和消息类型必须保持端到端绑定。

Token 使用高熵随机值；可评估成熟 PSK 握手模式及 Noise 等框架，具体握手、身份签名、密钥派生、重放窗口与轮换规则必须先冻结并审查，不能只靠共享口令加自制异或加密。[24]

## 10 MTU、分片与 ICMP 规则

### 内层 MTU 与外层 TCP 分段分开

建议三平台默认虚拟 MTU=1280，作为保守初值而非普遍最优值。IPv6 要求链路支持至少 1280 字节；内层 MTU、最大覆盖包、载体消息尺寸与封装缓冲必须一致。[13]

在 TCP Carrier 上，完整 IP 包可由长度帧传输并被外层 TCP 分成多个段，因此不应机械套用“物理 MTU 减所有隧道头”来计算虚拟 MTU。以后采用原生数据报 Carrier 时，必须重新处理路径最大消息尺寸、封装开销及分片 / 重组策略。[9][16]

第一版统一最小支持 MTU，避免换路后才发现备用路径不能承载。设备 MTU 下调或出口 PMTU 变化要产生明确事件；不在内存中无限重组大包。

### IP 分片与访问控制

默认不改写正常 IP 包，允许受控的 IPv4 / IPv6 已分片流量；接收端内核负责最终重组。非首片不一定包含端口，不能把“解析不到端口”当作允许通行。端口级 ACL 需要有界分片跟踪或有界重组；状态不完整时等待或丢弃并记录，不能绕过策略。

IPv4 DF 超长包与 PMTU 错误按相应协议处理；IPv6 路由器不能像 IPv4 那样中途分片，需处理 ICMPv6 Packet Too Big。初版不支持 IPv6 jumbogram，扩展头解析设数量、长度与处理预算上限。[13][15][19]

### ICMP 不是“代发一次 ping”

需要透传 Echo Request / Reply，也要正确传递不可达、超时和 MTU 相关错误。普通远端错误由目标内核产生并通过虚拟网卡回传；只有本地确认无路由、策略或尺寸问题时，才由明确的错误生成模块按规范产生必要响应。[14][15]

不把 ICMP 伪装成带“端口”的 UDP。ICMPv6 校验包含伪首部；生成错误时引用正确原包内容、限速，避免错误对错误的循环响应。禁止用虚假的 Echo Reply 掩盖目标离线。[14][15]

### 隧道跳数与 IP 跳数

本网将 Overlay 视为虚拟链路：每个中继只递减 OverlayHopLimit，不因经过一个 Relay 就改内层 TTL / Hop Limit。真正作为 IP 网关转发到别的网络时，另按 IP 转发语义处理。普通 traceroute 不承诺显示所有 Overlay 中继；另提供 mesh trace 诊断。

## 11 节点身份、地址与链路状态

保留 v0.1 的最小配置原则。首次运行自动生成并持久化身份，NodeID 从身份公钥派生；NetworkID 从协议命名空间、规范化名称与网络前缀生成，Token 不参与 NodeID / NetworkID。复制配置可以，复制正在使用的身份状态不可以。

### 地址声明与冲突收敛

从历史地址或 NodeID 派生候选地址，同步可达邻居后发布带身份签名的地址声明。声明包含所有者、地址、版本和有效期；自动地址冲突按固定 NodeID 排序决定保留方，另一方重新分配。固定地址优先于自动地址；两个固定声明冲突必须明确失败。

网络分区内可以继续工作，但无法保证分区合并后绝无地址冲突。地址变化会影响绑定旧虚拟 IP 的宿主 TCP 连接；这是比纯 SDK 更强的限制。改址时撤销旧声明、更新设备 / 路由、通知应用，不能保证旧连接续存，也不得把旧目标映射静默指向另一节点。

默认不运行 DHCP、不通过 ARP 广播分配地址。IPv6 可选前缀必须是全网一致配置；链路本地作用域、地址就绪和必要邻居发现行为由平台后端专门处理，不把组播扩散到全部中继。

### 已认证的双向连接构成拓扑

上游只规定主动连接对象，认证后的邻接双向使用。允许零上游节点接受入站；无任何连接时保持孤立。并行 TCP / WS 链路有独立 LinkID；多个上游共享同一故障域时不算独立容灾路径。

发布 Node / Link / Address / Capability 通告，维护链路状态数据库并本地计算路径；借鉴链路状态思想，不实现完整 OSPF。[25] 通告含持久化递增 incarnation、世代内 sequence、过期信息与签名；重复收到同一版本不得续命。

### 只发布真正可用的能力

packet.ipv4 / packet.ipv6 表示端点能投递相应 IP 包；endpoint.tcp / udp 表示具备对应出口；relay 表示允许中继；resume.stream 表示双方可协商恢复。仅配置了 TUN 但设备未就绪时不能发布 packet ready。中继只须支持覆盖消息，不能要求它实现目标业务协议。

## 12 路由稳定性与主备切换

先过滤身份 / ACL、不可用链路、禁用中继、跳数限制和载荷能力，再比较路径成本。为活跃目标保留 2～3 条候选，优先选择不同中继或故障域的备用；相同成本按稳定 ID 顺序决胜。

### 内置健康指标

平滑 RTT、波动、有效探测超时、发送排队时间、近期重连和数据面进展。TCP 探测超时不直接等于物理丢包率；服务端拒绝、ACL 拒绝和网络故障要分开统计。[9]

```text
edge_cost = 1 + rtt / 50ms + 0.5 * jitter / 20ms
          + 3 * probe_timeout_rate / 0.05
          + queue_wait / 20ms
          + 0.5 * reconnects_in_last_5min
path_cost = sum(edge_cost)
```

这是非负启发式成本，不是路径成功概率。RTT / 波动平滑可参考 RFC 6298；应用故障计时器不应直接等同于 TCP RTO。[20]

| 项目 | 建议初值 |
| --- | --- |
| 探测周期 | 2 秒，加入随机抖动。 |
| 普通指标发布 | 最多每 5 秒一次；变化不足不发布。 |
| 通告刷新 / 有效期 | 15 秒 / 45 秒，冻结明确老化与时钟容差。 |
| 性能切路 | 成本改善至少 20%，有绝对差下限，连续 3 窗口成立。 |
| 优化冷却 / 最大跳数 | 30 秒 / 16 跳；硬故障不受冷却限制。 |

### Path 安装与故障处理

源端选择无重复节点的路径，安装 PATH_OPEN / READY，之后以 PathID / Generation 转发消息；中继不任意改变下一跳，避免不同拓扑视图导致环路。下游断开时通过仍可达的控制方向反馈 PATH_BROKEN；超时和端到端数据探测补足反馈丢失。

Packet / UDP 消息按流或目标固定路径以减少重排，故障时后续消息改走备用；不要每包轮询不同路径。Stream Circuit 保持原绑定，除非协商恢复。性能优化优先影响新流，活跃包流可在空闲边界或受控迁移时换路。

备用应对活跃目的保持就绪或可快速安装，不为所有节点两两建立全套热备。控制流正常不代表数据链路正常，应同时监测真实承载队列和端到端进展。

## 13 TCP 外层的性能代价与恢复语义

### 能承载不等于保持原生时延特征

IP 包封装进 TCP 后，UDP / ICMP 也受外层可靠、有序交付约束；内层 TCP 与外层 TCP 都具有重传和拥塞控制。由此可推导出丢包时排队与恢复耦合的风险。多路复用只改善逻辑调度，无法消除同一物理 TCP 的队头阻塞。[9][10]

建议物理连接池区分控制、低时延包流和批量数据，按负载自动启用而不增加必填项。只在同一 TCP 上设置高优先级控制流不等于物理隔离；不同连接也不一定拥有不同网络故障域。

UDP / ICMP 队列设置字节数、包数和最大排队时间；拥塞时丢弃过期消息，不进行业务重放。已写入 TCP 内核缓冲的数据不能任意抽出，不能承诺绝不出现迟到包。后续允许可选原生数据报 Carrier，但纯 TCP 部署始终保留兼容路径。

### 不同数据平面的恢复契约

| 流量 | 换中继路径后的实际能力 |
| --- | --- |
| TUN 原生 TCP | 不改变两端 TCP socket 与虚拟 IP；内层 TCP 可重传并继续，但受业务超时、断网时长和端点存活限制。[9] |
| TUN UDP / ICMP | 后续包可换路；中间丢失、重排、迟到不由 Overlay 默认补偿。 |
| SOCKS5 UDP | 保持同一关联与出口 socket 时可换路径；失去出口状态就不能承诺原端口不变。 |
| 普通代理 TCP / CONNECT | Circuit 断开时默认返回错误；不能重新拨号冒充原连接。 |
| 可恢复代理流 | Session 维护偏移、ACK、重放缓冲、Epoch；两端状态和真实出口连接仍在时才允许续传。 |

**修正 v0.1 的表述：**“换路只能影响新 TCP 连接”仅适用于默认的终止式 Stream 代理，不适用于本版原始 IP 透传。Packet 平面不需要为了维持端点 TCP 状态而自建一套字节流恢复协议。

代理恢复 ACK 只代表会话层保留字节，不代表业务事务提交。端点重启、改 IP、出口 socket 关闭或恢复期限超限都应明确失败；HTTP 结果未知时仍不能擅自重复执行。[6]

## 14 Go 接口：配置与系统包设备

以下为可编译的接口草案，不包含实现。最小字段不变，Agent 的默认接入策略由配置规范化层填充。

```go
package overlay

import (
    "context"
    "net"
)

type Config struct {
    Listen    []string      `yaml:"listen"`
    Upstreams []string      `yaml:"upstreams"`
    Network   NetworkConfig `yaml:"network"`
    Inbounds  InboundConfig `yaml:"inbounds"`
}
type NetworkConfig struct {
    Name  string `yaml:"name"`
    CIDR  string `yaml:"cidr"`
    Token string `yaml:"token"`
}
type InboundConfig struct {
    TUN       *bool  `yaml:"tun"`
    SOCKS5    string `yaml:"socks5"`
    HTTPProxy string `yaml:"http_proxy"`
}
type DeviceEvent struct {
    Kind string
    MTU  int
    Err  error
}
type PacketDevice interface {
    ReadPacket(ctx context.Context, dst []byte) (int, error)
    WritePacket(ctx context.Context, packet []byte) error
    MTU() int
    Events() <-chan DeviceEvent
    Close() error
}
```

TUN 使用 *bool 区分“未配置”和 false。真实 YAML 解析采用严格字段校验，防止 tun 拼错却静默启用；状态目录、ACL、MTU 等可通过 Option 或独立选填块注入。

PacketDevice 一次调用对应一个完整 IP 包；缓冲不足返回明确错误，不能截断后当完整包处理。WritePacket 返回后不再持有调用方缓冲；ReadPacket 把数据复制到调用方缓冲。第一版允许一个读者和一个写者并行，关闭须唤醒阻塞操作；批量与零拷贝由独立扩展接口提供。

macOS 包装头、Windows ring 指针和 Linux offload 元数据都由后端处理，不泄露进 PacketRouter。SystemNetwork 配置事务与 PacketDevice I/O 分离，便于 Agent 管理权限，也便于测试时挂载内存设备。

## 15 Go 接口：Flow、消息与扩展点

以下声明与上一节放在同一包中，使用已导入的 context / net。Stream 与 Datagram API 分开，不把 UDP 伪装成连续字节流。

```go
type NodeID string

type Stream interface {
    net.Conn
    CloseWrite() error
    Reset(code uint32) error
    RemoteNode() NodeID
}
type EndpointAddr struct {
    Host string
    Port uint16
}
type Datagram struct {
    Remote  EndpointAddr
    Payload []byte
}
type DatagramSession interface {
    Send(ctx context.Context, msg Datagram) error
    Receive(ctx context.Context) (Datagram, error)
    Close() error
}
type Network interface {
    DialContext(ctx context.Context,
        network, address string) (Stream, error)
    Listen(network, address string) (net.Listener, error)
    OpenDatagrams(ctx context.Context) (DatagramSession, error)
    AttachPacketDevice(ctx context.Context, d PacketDevice) error
    Close() error
}
```

Send 中 Remote 是目的地，Receive 中 Remote 是真实来源；域名须经解析与授权后才能出口。Send 成功仅表示消息已被本地有限队列接受，不代表远端交付。发送返回后不保留输入切片；接收数据归调用方所有。DatagramSession 另限制最大消息、目的数、并发和空闲时间。

AttachPacketDevice 仅挂载 I/O，不隐式改系统路由。UDP 服务端监听可在后续公开 PacketListener / net.PacketConn 适配；SDK 不应因一个 TCP 专用 Dial 返回类型而模糊 UDP 能力。

Carrier 统一登记 Stream 能力及可选 NativeDatagram、MaxMessageSize 等属性。TCP-only Carrier 通过长度帧承载消息；未来原生数据报实现不应被接口强制套进 net.Conn。Endpoint / Adapter 按能力显式协商，不支持就失败，不降级伪装。

每条 Stream 的 Deadline、取消、FIN、RESET 必须隔离，不能写到共享物理连接上。协议适配器和路由器通过结构化错误通信，不依赖错误字符串决定重试。

## 16 安全、DNS 与出口策略

### 默认同网互访，但不是开放代理

共享 Token 表示一个信任域，不等于每个成员天然可信。加入、转发、访问端口、发送 ICMP、使用网关分别授权。Token 不写日志、不作为本地代理用户名 / 密码重复使用；更细的成员撤销与平滑轮换是可选管理功能。

Packet 入口验证内层源地址属于认证源节点声明的地址或明确授权前缀，目的地址与最终投递者一致；不能只验证逐跳 TLS 后就允许伪造任何虚拟源 IP。分片、IPv6 扩展头与 ICMP 引用包也必须经过有界解析。

默认网络层允许成员访问虚拟接口上的 TCP / UDP 及必要 ICMP；宿主防火墙与应用认证继续生效。通配监听服务可能因此对同网成员可达，应在启动诊断中提示暴露范围。不得为了通过 ping 自动关闭防火墙。

### DNS 不隐式改变信任边界

直接访问虚拟 IP 无需 DNS。需要名称时可增加内部解析器，把可选节点别名映射到地址声明；默认不改系统 DNS。代理收到域名时先解析，随后按实际 IP 再次检查 ACL；连接时固定已验证地址，避免 DNS 重绑定和解析 / 拨号不一致。

虚拟域名只由内部解析器处理；普通外部域名在没有显式出口时拒绝。选择出口代理后，由明确的解析策略决定本地还是出口解析，不能失败后静默改为本机直连。TUN 处理的是 IP 包，本身不能保证捕获应用通过其他接口发送的 DNS。

### Gateway 是可选角色，不是上游的同义词

网内 TCP / UDP 代理出口是 SocketEndpoint；网外 L3 出口还需要路由、回程策略及可能的 NAT。必须显示配置允许的前缀和来源，默认不接受其他节点宣告的 0.0.0.0/0 或 ::/0。

L3 网关转发需正确处理 TCP、UDP 和 ICMP 错误的映射及引用包校验。发生 NAT 时，出口状态与源地址是会话的一部分；改变中继路径可以保留它们，更换网关不能自动视作无损。与 Packet 直通不同，公网出口不承诺保留原虚拟源 IP。

### 有界资源与失败行为

限制握手、邻居数、通告大小、流数、关联目标数、包队列、分片缓存和全局内存；控制面设速率限制。认证 / 策略失败不通过绕路重试；无路由、路径断开和服务拒绝分别报告。未知强制能力直接拒绝，不能忽略后继续互通。

| Linux / Windows / macOS | 六种异系统有向组合，加三种同系统组合；分别验证 TCP、UDP、ping。 |
| 多跳与反向访问 | 两端只主动连接同一中继，也可双向访问；纯中继不创建 TUN。 |
| Packet TCP 换路 | 保持虚拟 IP 与真实端点 socket；断主路后验证继续传输及超时边界，不注入伪造 RST。 |
| UDP / ICMP 换路 | 记录丢失、重复、重排与迟到；不进行隐藏业务重放。 |
| SOCKS5 UDP | TCP 关联关闭回收、多个目的地、来源校验、FRAG 不支持时丢弃、出口端口稳定。 |
| HTTP / WebSocket | CONNECT、流式上传 / SSE、取消、101 转发、半关闭、连接池、非幂等请求不盲重试。 |
| MTU / IP 分片 | 大 UDP、IPv4 DF、PMTU、端口 ACL 不被非首片绕过；启用 IPv6 后覆盖扩展头与 ICMPv6 PTB。 |
| 系统生命周期 | 无权限、缺驱动、路由冲突、端口占用、睡眠唤醒、Wi-Fi 切换、崩溃重启和清理。 |
| 安全与容量 | 错 Token、伪造地址 / 通告、重复密文、过大帧、慢读端、控制面洪泛、有限内存和速率。 |

性能测试要同时给出吞吐、RTT、p95 / p99 排队时延、内存、CPU、切路检测时间和有效恢复时间；尤其在外层有延迟、抖动与丢包时测试 UDP / ICMP，不能只用零丢包局域网结果作承诺。

### 需要可解释的状态

status 展示实际 NodeID、虚拟 IP、设备类型 / 名称、路由安装情况、已认证邻居及接入端口。routes 展示主备路径、成本与共享故障点；trace 展示 Overlay 跳点；doctor 检查权限、驱动、地址池、物理绕行、DNS 和防火墙相关证据。

指标区分设备读写包数、IP 包丢弃原因、UDP 队列年龄、Stream 数、Association 数、Path 安装失败、MTU 错误、未知目标与出口拒绝。连接健康和应用可达性不混为一个绿色状态。

### 第一版建议默认值

虚拟 MTU 1280；最大 Overlay 跳数 16；候选路径最多 3；未配置代理不监听；Agent 默认系统网卡，库默认无系统副作用；回环以外无认证代理默认拒绝；只安装虚拟前缀路由；不启用公网 / LAN 网关；Packet 不自建可靠重传层。

健康参数采用第 12 节初值，UDP 关联空闲初值 120 秒，所有连接、队列、帧、分片及全局内存都有硬上限。具体容量应由部署档位产生，不随节点数量无限增长。

### 实现前必须冻结

冻结版本与能力协商、握手与密钥派生、地址声明 / 撤销 / 老化、Path 失效反馈、帧编码与尺寸、消息所有权、Packet / UDP / Stream 不同失败语义、IP 分片策略、MTU 与 ICMP 生成规则，以及三个系统的地址 / 路由清理契约。

单独记录兼容边界：v0.1 仅理解 Stream 的节点不能作为 IP_PACKET 的可用端点；不能静默把 Packet 流量降级为 TCP 代理。依赖版本、操作系统支持范围和签名 / 分发条件在发布清单中锁定，不以“可交叉编译”代替系统验证。

**最终基线：五类组网配置不变，TUN 提供原生三层互访，SOCKS5 / HTTP 提供各自标准范围内的代理接入，所有模块共享认证、拓扑与路由，但不混淆传输语义。**
