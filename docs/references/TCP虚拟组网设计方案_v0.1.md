# 轻量 TCP 虚拟组网设计方案

**最小配置 · 动态路由 · 可扩展 Go 库**

版本：v0.1（设计草案）  |  日期：2026-09-21

## 01 方案概览

设计目标是构建一个可嵌入应用的 Go 网络库及可选独立节点程序。每个节点只填写监听地址、零到多个上游，以及网络名称、虚拟网段和认证 Token；身份生成、虚拟 IP 分配、拓扑发现、稳定性评估与主备选路由系统完成。

> **核心决策：** 采用“TCP 服务型覆盖网络”：以虚拟 IP＋端口对外寻址，以稳定 NodeID 识别节点，以链路状态选择路径，以固定 Circuit 承载业务流。传输载体与业务协议各自扩展，互不耦合。

### 范围与交付形态

| 项目 | v0.1 设计基线 |
| --- | --- |
| 组网能力 | 对等节点、多跳 TCP 中继、多上游、双向访问、自动主备选路。 |
| 最小配置 | listen、upstreams、network.name、network.cidr、network.token；其他配置均选填。 |
| Go 库 | 提供虚拟 Dial / Listen；默认不创建网卡、不修改宿主机路由。 |
| 独立 Agent | 在具备系统权限时提供虚拟接口与系统 TCP 接入；复用同一套核心。 |
| 协议扩展 | 独立支持 TCP、WebSocket、HTTP 隧道及未来私有载体；业务适配器单独注册。 |

### 能力边界

**不是完整三层 VPN。** 默认承载 TCP 字节流，不提供 UDP、ICMP 或任意 IP 分组透传；代理模式不保证目标应用看到原始来源 IP。

**自动切路不等于长连接无损迁移。** 第一阶段自动为新建业务流选择可用线路；已有流固定路径，断线后返回明确错误。跨路径续传属于后续独立会话层。

**自动地址分配不等于地址永不变化。** 地址尽量稳定；网络分区合并后允许冲突收敛。不存在可达连接时，节点保持孤立。

## 02 最小配置与默认规则

```yaml
listen:
  - "tcp://0.0.0.0:7000"

upstreams:
  - "tcp://relay-a.example.com:7000"
  - "ws://relay-b.example.com:7001"

network:
  name: "my-network"
  cidr: "10.77.0.0/24"
  token: "${MESH_TOKEN}"
```

同一虚拟网络内的 name、cidr 和 Token 必须匹配。上游地址必须包含协议、主机和端口；仅有协议与端口不足以定位远端。cidr 是全网地址池，不是本节点地址。

| 字段 | 配置契约 |
| --- | --- |
| listen | 接受入站连接的地址列表；载体可要求额外 URL 路径，采用约定的缺省值。 |
| upstreams | 主动连接地址列表；允许为空或省略，省略视为空列表。 |
| network.name | 网络名称；在握手中参与网络一致性校验。 |
| network.cidr | 规范化后的虚拟地址池；第一阶段以 IPv4 单网段为实现范围。 |
| network.token | 共享入网凭据。支持环境变量替换，变量不存在或结果为空时拒绝启动。 |

### 内置默认行为

自动生成并持久化节点身份；自动分配虚拟 IP；认证后的连接双向使用；默认允许同网络节点中继与访问已接入的虚拟 TCP 端口；自动同步拓扑、重连上游、选择主备路径。不默认连接公共引导节点，也不开放互联网或物理局域网出口。

### 可选配置的范围

`options` 可覆盖固定 IP、状态目录、是否中继、访问策略、路由参数、会话模式和日志级别；`adapters` 可声明额外业务入口或出口。未填写时采用完整默认值，不要求用户指定算法、证书路径或节点 ID。

> **启动校验：** 未知协议、空 Token、无效网段、地址池耗尽、状态目录不可用必须给出明确错误。Agent 还需校验系统权限与网段冲突。上游暂不可达不等于配置错误：节点可继续监听并退避重连。

## 03 节点、拓扑与自动地址管理

### 上游只决定拨号，不构成父子关系

```text
A.upstreams = [R1, R2]     B.upstreams = [R1, R2]
R1.upstreams = []          R2.upstreams = []

A <----> R1 <----> B
A <----> R2 <----> B
```

连接完成认证后，两端都能发起逻辑流。零上游节点可以接受入站连接；无任何连接时保持孤立。默认不自动建立全互联，也不承诺所有 NAT 环境都能直接穿透。多个上游若共享同一中继或故障域，不能视为完全独立的容灾线路。

### 三个标识必须分离

| 标识 | 生成与稳定性规则 |
| --- | --- |
| NodeID | 由本节点长期身份公钥派生；不依赖 IP、网段或 Token。首次生成后持久化。 |
| NetworkID | 由协议命名空间、网络名称、规范化 CIDR 确定；Token 不参与身份计算。 |
| VirtualIP | 从网段分配的地址；优先复用历史值，但必须接受冲突检测与必要改址。 |

### 地址分配与冲突收敛

启动时先加载历史地址并同步可达邻居的声明；历史地址可用则复用，否则依据 NodeID 选择确定性的候选地址。声明包含 NetworkID、NodeID、VirtualIP、版本、有效期与签名；收到声明后验证身份与版本，不能只依赖中继转述。

两个自动声明冲突时，按固定 NodeID 排序确定保留者，另一方尝试新候选；候选空间耗尽则明确报错。网络分区恢复后沿用相同规则收敛，不宣称任意分区下仍能保持全局唯一且永不改址。

选填固定地址优先于自动地址。两个固定地址冲突时拒绝静默改址并报告冲突。业务流建立时绑定目标 NodeID，后续 IP 映射变化不得将旧流改投给其他节点。

> **持久化规则：** 保存身份密钥、启动世代、地址声明版本与上次虚拟 IP。允许复制配置，不允许克隆正在使用的身份状态；同机多实例通过选填 state_dir 隔离。更换 Token 不改变 NodeID，但凭据轮换仍需独立的生效与撤销流程。

## 04 分层架构与两种接入形态

| 模块 | 职责与边界 |
| --- | --- |
| Adapter 业务适配 | TCP、HTTP、WebSocket、私有协议的入口和出口；拥有业务解析与重试语义。 |
| Endpoint / Policy | 解析虚拟 IP＋端口、服务注册与访问授权；ServiceID 仅作为选填高级寻址。 |
| Session 会话 | 源端与目的端的身份绑定；普通流，以及后续可恢复流与端到端安全能力。 |
| Circuit 线路 | 按指定路径建路、多跳转发、半关闭、取消、资源释放。 |
| Routing / Health | 拓扑约束、链路测量、候选路径、迟滞切换；不解析业务报文。 |
| Link 邻接 | 已认证连接、双方主动开流、多路复用、反压与链路资源限制。 |
| Carrier 载体 | TCP、WS/WSS、HTTP 隧道、私有载体；输出统一的双向流能力。 |

控制平面向 Circuit 提供路径，不参与每个数据块的选路。中继只理解覆盖网络协议，不必安装目标业务的 HTTP、WebSocket 或私有协议适配器。

### Go 库模式：虚拟端口属于应用

```text
服务端：node.Listen("tcp", ":8080")
客户端：node.DialContext(ctx, "tcp", "10.77.0.23:8080")
```

库内监听只开放应用主动注册的虚拟端口，不自动暴露宿主机端口，也不要求配置每个 ServiceID。返回标准连接与监听器契约，方便接入现有 Go 代码。

### Agent 模式：普通应用通过系统接入

```text
普通 TCP 应用 -> 虚拟接口 / 用户态 TCP 接入
              -> Circuit -> 目标节点 TCP 出口
              -> 目标节点虚拟 IP 上的服务
```

TUN 提供 IP 分组接口，不是现成字节流；Agent 需要用户态 TCP 接入或等效系统机制，并具备创建接口与路由的权限。[8] 可评估现成用户态网络栈，不把从零实现 TCP 纳入第一阶段。[11]

> **默认暴露边界：** Agent 只允许出口连接本节点虚拟地址的目标端口。仅绑定 127.0.0.1 的服务须显式映射；监听所有地址的服务可能同时接受虚拟接口连接，应受宿主机和覆盖网络策略约束。系统权限不足时明确失败，不静默伪装为透明组网成功。

## 05 控制平面与路径计算

### 采用链路状态同步

每个节点维护已认证节点、地址声明、邻接链路和可选服务信息。通过传播链路状态构建拓扑，再在本地计算路径；借鉴链路状态数据库与最短路径思想，不实现完整 OSPF。[2] 初期面向几十至几百节点，规模上限以实际压测确定。

```text
Advertisement {
  network_id, origin_node_id,
  incarnation, sequence, issued_at, expires_at,
  links[], addresses[], services[], capabilities,
  signature
}
```

incarnation 在启动时持久化递增，sequence 在该世代内递增；随机 BootID 只能区分进程，不能判断新旧。只通告已建立且完成认证的链路；远端边建议由两侧匹配 LinkID 的通告确认。并行载体保留各自的 LinkID 与健康指标。

### 同步与老化规则

邻接建立后执行身份认证、版本与能力协商、版本摘要交换、分页补齐和增量同步；周期核对摘要修复遗漏。重复收到相同版本不得延长有效期，转发不得刷新原始寿命；撤销信息保留至旧声明不再可能有效。失效边在本地立即排除，不等待全网收敛。

| 事件 | 建议默认处理 |
| --- | --- |
| 邻接建立 / 断开 | 立即触发更新，允许短窗口合并重复事件。 |
| 普通指标变化 | 最多每 5 秒发布一次，且变化达到阈值；不广播每次测量。 |
| 定期刷新 / 过期 | 刷新 15 秒、有效期 45 秒；具体老化与时钟容差协议需冻结。 |
| 恶意或超量通告 | 限制大小、分页量、发送频率与每源状态量，校验版本及签名。 |

### 先过滤，再排序

先排除不可达、拒绝中继、策略不允许、跳数超限或承载能力不满足的路径；再按非负成本排序。业务协议能力只需在源与目的端匹配，不能要求中继理解业务。

为每个目标保留最多 3 条候选路径；先计算主路径，再尽量避开主要中继或共享故障域计算备用。相同成本按稳定的 NodeID / LinkID 顺序决胜，避免无意义跳动。

## 06 稳定性评估与动态切路

### 测量对象与指标边界

| 指标 | 使用方式 |
| --- | --- |
| 平滑 RTT / 抖动 | 体现时延与波动，不使用单次探测直接触发切路。 |
| 探测超时率 | 衡量期限内未收到有效响应的比例；不是底层真实 IP 丢包率。 |
| 发送排队时间 | 识别局部拥塞，同时区分下游业务不读与网络故障。 |
| 近期重连频率 | 对频繁断开路径施加衰减惩罚，避免刚恢复就抢回主路。 |
| 业务与服务结果 | 建路失败用于线路诊断；服务拒绝或权限失败不污染整条链路。 |

TCP 会重传并向应用提供有序字节流，因此应用探测超时不能直接命名为丢包。[1] RTT / 波动采用平滑更新，可参考 RFC 6298 的估计方式，但应用失活窗口不等于 TCP 重传计时器。[3]

### 可实现的初始成本

```text
edge_cost = 1
  + rtt / 50ms
  + 0.5 * jitter / 20ms
  + 3.0 * probe_timeout_rate / 0.05
  + queue_wait / 20ms
  + 0.5 * reconnects_in_last_5min
  + admin_cost

path_cost = sum(edge_cost)
```

admin_cost 默认为 0。成本仅用于相对排序，不是成功概率模型。链路 RTT 之和是近似指标；对活跃主备路径追加低频端到端验证。吞吐能力不能相加，后续可针对 interactive、bulk、stable 设置内置业务类别。

### 故障与优化采用不同规则

**硬故障：** 明确读写错误或连接关闭立即排除链路；连续缺少有效回应，达到自适应失活窗口后判定不可用。默认探测周期可从 2 秒加随机抖动开始，迟到旧 PONG 不能证明恢复。

**性能优化：** 建议新路径成本低至少 20%，同时达到绝对差下限，连续 3 个评估窗口成立，并距离上次优化切换超过 30 秒，才更新新建流的首选路径。硬故障不受冷却限制。

> **恢复策略：** 恢复链路先观察，再逐步接收新流量。上述数字均为建议初值；绝对差下限、窗口长度、指标封顶和失活上下限需通过目标网络测试确定，不承诺固定毫秒级故障恢复。

## 07 Circuit、会话与故障语义

### 源端指定无环路径，中继严格执行

```text
CircuitOpen {
  circuit_id, destination_node,
  hops: [ {node, link_id}, ... ],
  cursor, hop_limit, remaining_budget
}
```

源端选择无重复节点的路径。每个中继校验自身位置、LinkID、跳数与剩余预算，建立“入站逻辑流 ↔ 出站逻辑流”。下一跳失败就返回错误，由源端尝试备用；不允许中继任意局部改路。各跳消耗同一剩余时间预算，不重新获得完整超时。

线路建立后，源与目的端验证彼此身份，目的端检查虚拟端口权限并完成出口打开，再返回 READY。之后 DATA 按已有线路转发，无需逐块查路由。FIN 只结束一个发送方向，RESET 只终止当前业务流，不关闭整个邻接连接。

### 三个能力等级必须分开

| 模式 | 线路失效后的行为 |
| --- | --- |
| PinnedStream（默认） | 新建流自动改走备用路径；已有流返回错误，不伪装成无损恢复。 |
| 请求级重试（适配层） | 仅在业务语义允许、请求可重放且结果状态满足策略时重试；路由层不决定重复执行。 |
| ResumableStream（后续） | Session 与 Circuit 解耦；在两端会话状态仍存在等条件下，可暂停并跨路径续传。 |

普通 TCP 的底层 IP 路由变化不同于替换覆盖网络中的 net.Conn；后者不会继承旧连接状态。[1] HTTP 非幂等请求也不能因线路失败就被代理自动重放。[4]

### 恢复层的必要状态

至少保存 SessionID、双方身份、Epoch、双向字节偏移、确认位置、未确认缓冲、接收窗口、FIN 状态、恢复凭据与恢复期限。新 Circuit 建立后交换确认位置，重放未确认字节并去重；提升 Epoch 隔离旧线路迟到数据。

> **恢复承诺：** ACK 仅代表会话层按约定接收并保存字节，不代表业务事务提交。缓冲达到上限后必须反压；端点重启丢失状态、出口真实连接关闭或恢复超时，都应明确失败。保持的是端到端虚拟流，不是重新拨一条业务连接冒充原连接。

## 08 载体与业务协议扩展

### 两类扩展点不混用

| 扩展点 | 示例与契约 |
| --- | --- |
| Carrier：节点如何连接 | tcp、ws/wss、HTTP CONNECT、未来私有载体；输出可靠、有序、双向的流，并显式协商能力与限制。 |
| Adapter：业务如何接入 | TCP 转发、HTTP 反向代理、WebSocket 消息、私有协议；负责消息语义、取消、认证映射与请求级重试。 |

使用 URL Scheme 注册载体；WS 的缺省路径可统一为 /mesh，显式 URL 可覆盖。未知 Scheme 拒绝启动，不自动降级。每一跳可以使用不同载体，中继仍只处理统一线路协议。

### HTTP、WebSocket 与非流式请求

| 形态 | 实现规则 |
| --- | --- |
| 原样 TCP 业务 | 字节流转发即可承载上层 HTTP、WebSocket 或私有协议，无需中继解析。 |
| HTTP 请求 / 流式响应 | Body 增量读写，支持取消、期限与 Flush；请求—响应形式不意味着全部缓冲在内存。 |
| WebSocket 消息接入 | 终止并重建 WS 时显式保留类型、消息边界与关闭语义；不能以一次 Write 对应一次 Read。[6] |
| HTTP CONNECT 载体 | 建立隧道后再承载双向流；HTTP/2 CONNECT 的隧道属于单个 HTTP/2 流。[4][5] |
| HTTP 短请求载体 | 独立 httppoll 适配器实现上行发送、下行轮询、序号、确认、去重、有限邮箱和反压；后续实现。 |

### 连接复用、流式行为与重试

HTTP 适配器需验证全路径的双向读写、代理缓冲、空闲超时与 Flush 行为。Go HTTP/1 服务端按需启用全双工处理；HTTP/2 具有不同的并发读写行为，不应假设所有代理都支持相同行为。[7]

http.Transport 会复用连接，因此更新路由表不等于下一个请求必走新路。可按路由代际新建连接池，旧池停止接收新请求后逐步排空；关闭空闲连接不迁移在途请求。[7]

结果未知时禁止默认重放。IdempotencyKey 只有配合服务端去重才有意义，跨实例重试时去重范围也必须覆盖相关实例。私有协议的重试与恢复由其适配器声明，不写进 Routing。

## 09 安全、资源治理与可观测性

### Token 简化配置，不替代安全设计

建议 Token 使用 32 字节安全随机值的编码，不使用短口令。节点身份密钥由系统生成；Token 仅证明入网资格，不作为 NodeID。底层 TCP、WS 或 HTTP 建立后，必须先执行内部安全握手，再开放拓扑与业务通道。

安全握手需绑定 NetworkID、节点静态身份、协商版本和能力，禁止认证失败后降级。可评估成熟 PSK 安全握手模式，例如 Noise 的相关模式，但不能把“有 Token”直接当作已解决身份绑定、重放防护与密钥管理。[9] 具体安全协议属于实现前必须冻结的设计。

相邻链路认证与源端身份认证分离；目的端不能只相信中继填写的 source_node。相邻加密不代表中继无法读取业务；不信任中继时由 Session 层提供端到端加密。WSS 外层可能在代理处终止，不能代替内部节点认证。

### 访问边界与成员管理

共享 Token 对应同一个默认信任域；持有者可加入并访问默认策略允许的虚拟端口。加入网络、参与中继、访问目标端口是三个独立授权点。按节点撤销、细粒度 ACL 与平滑 Token 轮换属于可选管理能力；Token 不记录到日志或诊断输出。

### 有界资源与反压

对每 Peer 连接数、并发建路、活跃流、帧大小、收发窗口、待同步通告、全局内存和恢复缓冲设定硬上限。慢接收端导致窗口收缩与反压，不触发无限内存队列；统计预算必须包含多路复用库的内部窗口。

共享 TCP 连接的逻辑流仍可能受底层队头阻塞影响，HTTP/2 也不消除这一点。[5] 控制流优先级并非物理隔离；实现上预留独立控制连接及交互 / 批量连接池，按需求启用。

### 必须可解释的运行状态

| 观测对象 | 至少暴露 |
| --- | --- |
| 节点 / 地址 | NodeID、虚拟 IP、已认证邻居、地址冲突与收敛状态。 |
| 路径 / 链路 | 主备路径、成本、共享故障点、排除原因、RTT、超时与重连。 |
| 业务 / 资源 | 活跃 Circuit、错误类型、缓冲与配额占用、出口失败。 |
| 切换 / 恢复 | 触发原因、故障检测耗时、建路耗时；启用恢复时另记恢复耗时。 |

## 10 Go 库公开接口草案

公开配置只暴露最小入口；可选功能通过 Option 或 options 区块注入。下面只定义契约，不包含实现。第一阶段 network 参数仅支持 tcp，address 使用虚拟 IP＋端口。

```go
package overlay

import (
    "context"
    "net"
)

type Config struct {
    Listen    []string      `yaml:"listen"`
    Upstreams []string      `yaml:"upstreams"`
    Network   NetworkConfig `yaml:"network"`
}

type NetworkConfig struct {
    Name  string `yaml:"name"`
    CIDR  string `yaml:"cidr"`
    Token string `yaml:"token"`
}

type NodeID string

type Stream interface {
    net.Conn
    CloseWrite() error
    Reset(code uint32) error
    RemoteNode() NodeID
}

type Network interface {
    DialContext(ctx context.Context,
        network, address string) (Stream, error)
    Listen(network, address string) (net.Listener, error)
    Close() error
}
```

### 接口实现要求

DialContext 只在建路、端到端身份确认和目标端口打开成功后返回。Listen 返回的连接应满足 Stream；对接 http.Transport 时可薄封装为返回 net.Conn 的函数。每条流独立支持取消、Deadline、FIN 和 RESET，不把单流超时写到共享物理连接上。

CarrierDialer / CarrierAcceptor 独立负责拨号或接收原始双向流，以便复用现有 HTTP Server；安全升级与 LinkSession 位于其上。多路复用可评估 Yamux 等已有实现，但仍需自行提供路由和跨线路恢复。[10]

## 11 实施阶段、错误分类与验收

| 阶段 | 交付内容与验收边界 |
| --- | --- |
| P1：核心可用 | 最小配置、持久化身份、认证 TCP 载体、双向复用、地址声明、链路状态、主备路由、固定 Circuit、SDK Dial / Listen；已有流断线明确报错。 |
| P2：用户接入 | Agent 系统 TCP 接入、WS 与 HTTP 隧道、HTTP / 消息适配器、连接池排空、策略与观测完善；普通应用可使用虚拟 IP。 |
| P3：高级恢复 | ResumableSession、端到端偏移确认与重放、httppoll 载体、业务分类调度；发布恢复期限、缓冲和端点存活契约。 |

对最终用户的“五类配置启动即互访”体验，以包含 Agent 接入的阶段为交付口径；仅完成 SDK 不应宣称宿主机任意程序已经透明组网。

### 错误由正确的层处理

| 错误类别 | 处理规则 |
| --- | --- |
| NoRoute / LinkDown / RouteStale | 在剩余预算内尝试其他合法候选路径。 |
| PermissionDenied / ProtocolNotSupported | 明确失败；不得通过绕路绕过权限，不默认降级。 |
| TargetRefused / ServiceUnavailable | 更新目标端口或服务健康，不默认判整条链路失败。 |
| OutcomeUnknown / SessionLost | 交给业务或恢复契约处理，不自动重放，不伪装恢复。 |

### 首批验收场景

| 场景 | 通过条件 |
| --- | --- |
| 双向访问与双路径故障 | 两端主动连接中继后可相互开流；主路故障后新流走备用。 |
| 环路与拓扑暂时不一致 | 建路成功或有限失败，不无限转圈；超时预算不被逐跳重置。 |
| 地址冲突、分区与重启 | 旧通告不覆盖新状态；自动地址收敛；固定冲突明确报告。 |
| 抖动、慢端与大流量 | 不频繁切路；缓冲有界；控制面可诊断，不被无界业务队列阻塞。 |
| 半关闭、HTTP 流式与未知结果 | 关闭写方向后仍可读响应；增量传输；非幂等请求不被盲目重放。 |
| 安全与恢复专项 | 错误 Token / 网络拒绝接入；P3 另验收旧 Epoch 隔离与端点状态丢失处理。 |

## 12 工程组织、待冻结项与参考依据

### 建议包边界

```text
overlay/
  identity/   security/   policy/
  transport/  # tcp, websocket, httpconnect, httppoll
  link/       topology/   health/   routing/
  circuit/    session/    endpoint/
  adapter/    # tcp, http, websocket, private
  observability/
cmd/mesh-agent/
```

依赖方向固定为 Adapter → 核心接口；Routing 不依赖 net/http、WebSocket 库或私有业务 Codec。配置经校验、身份加载与默认值填充后生成内部 RuntimePlan，再启动监听、安全会话、同步和接入模块。

### 实现前必须冻结的协议细节

安全握手与密钥派生；通告编码、签名覆盖范围、启动世代与老化规则；地址冲突与固定地址优先级；Circuit 帧、半关闭、错误码和剩余预算；流控与全局配额。会话恢复另行冻结 ACK、Epoch、凭据、重放和状态丢失契约，不能用未定义行为先行宣称可用。
